# 01 — Vision, Opinion, Risks

## What you're building
Reverse-recruiting / talent marketplace:
- candidates create one deep profile once
- employers create job requirement
- system finds best candidates automatically
- candidates don't re-apply repeatedly

## What's good
- Candidates hate repeated applications — solves real pain.
- HR hates screening hundreds of resumes — helps them too.
- Structured talent database + AI matching can be very valuable if done well.
- Private (no candidate-to-candidate browsing) is a strong privacy feature.

## What's risky
- Free-text-only profiles = weak search.
- Marketing-fluff AI summary = recruiters won't trust.
- Fake / low-quality / outdated candidates = employers churn.
- Uncontrolled employer access = candidates won't trust.
- Generic "all jobs" at start = too broad, hard to grow.

## Biggest suggestion: niche-first
Do NOT start generic. Start with one niche, then expand:
- backend developers in one city
- frontend interns
- data analysts
- designers from one community
- one college ecosystem
- one country / region

Niche = easier growth + easier relevance.

## Hard parts are not just "AI search"
1. profile quality
2. trust / verification
3. privacy (revised to open-contact in this blueprint — see 09)
4. matching accuracy (needs deep understanding, not keywords)
5. getting enough good candidates + employers (cold-start)

## Value proposition that wins
Not "we have a database." Many have that.
Value = understand context, evaluate evidence, explain why candidate fits role.
Example: job needs "scalable systems" → candidate wrote "10k concurrent WebSocket via Redis + Node.js" → must match even without word "scalable."
